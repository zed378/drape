# R0-05 specification review

Date: 2026-11-26. Reviewer: a read-only `codex exec` session in the Windows and safety role, requested through the Claude Code coordinator. Status: findings open. The [R0-05 spec](../specs/R0-05-native-icon-recovery.md) is unchanged; no implementation, native evidence or acceptance is implied.

The report follows with dash punctuation normalised.

1. **A user change can race a toggle** Windows integration §3 requires a read before sending a toggle, but that does not serialize the toggle against changes made through the Windows menu. For example, during restore Drape reads `Hidden`, the user chooses `Show` and the state becomes `Visible`, then Drape sends its stale toggle and hides the icons again. A crash before recovery completes can leave them hidden and the user’s choice overwritten. **Smallest change:** specify and verify a mechanism that orders or detects user changes across the toggle. If the spike cannot establish one, define the result as ambiguous and prohibit automatic retry or restoration in that case.

2. **Intent-phase recovery cannot always establish ownership** The spec says to restore after a crash between hiding and recording active ownership, but does not define how recovery distinguishes Drape’s hide from a later user choice. For example, the record says the original state was visible; App and Guard both fail after Drape hides; the user then changes icons from hidden to visible and back to hidden. Next startup sees `Intent + Hidden`, indistinguishable from Drape’s hide alone. Restoring would override the user’s latest choice. **Smallest change:** define that this observation is ambiguous unless durable evidence proves no external change; specify the safe outcome and whether manual recovery is required.

3. **Standalone restore lacks a defined rehide-suspension transition** The spec says `--restore-desktop` must not let a live App immediately rehide, but does not say how the App enters or exits that suspended state. After a successful CLI restore, a queued quick-hide request could run and hide icons again. **Smallest change:** make a live-owner restore request latch the current generation in a restore-only state, reject queued hides, and define the event that explicitly rearms hiding.

4. **Timeout does not define safe fallback while the owner is still live** The spec permits standalone restore to ask a validated live owner and “otherwise” use a non-ambiguous record, but does not define whether an IPC timeout makes that fallback safe. A live but stalled App could resume after CLI restores from the record and hide icons again. **Smallest change:** make timeout with a still-live validated owner return pending/failed without record-based mutation; permit takeover only after the owner is positively fenced or confirmed dead under a new generation.

5. **Guard-failure outcome is ambiguous for initially hidden icons** The behavior table says “Keep icons visible/unchanged” on Guard readiness failure, while the spec says pre-hidden icons are not claimed and failed preconditions leave state unchanged. On an initially hidden desktop, those phrases allow different outcomes, including overwriting the user’s setting. **Smallest change:** say “leave the observed pre-transaction state unchanged; acquire no ownership.”

| Core state | Events | Transition |
|---|---|---|
| Unowned | Begin hide; recovery start; observe icon state | Visible → persist intent; already hidden → remain unowned; unknown → ambiguous |
| Intent pending | Intent persistence succeeds, fails, or is indeterminate | Success → await Guard; failure/uncertainty → safe or ambiguous, with no hide |
| Await Guard | Authenticated readiness; timeout; owner or host loss | Ready → armed intent; otherwise → safe/ambiguous, with no hide |
| Armed intent | Revalidate owner, Guard, host, and icon state; external change | Valid → hide pending; changed/unknown → unowned or ambiguous |
| Hide pending | Toggle result, readback, persistence result, crash | Verified hide and durable active record → owned hidden; uncertain result → recovery pending/ambiguous |
| Owned hidden | Restore request; user override; Guard loss; restart | Restore request → restore pending; override → drop ownership; Guard loss → rearm required |
| Restore pending | Restore verification; Explorer unavailable; owner timeout | Verified → persist success; unavailable/timeout → pending; external change → drop ownership/ambiguous |
| Success pending | Success record durable; record write failure | Durable success → disarm Guard; failure → retain retry state |
| Rearm required / restore-only | Explicit rearm; new authenticated Guard; stale hide request | Valid rearm → armed; otherwise reject hide |
| Ambiguous | Manual recovery choice or new validated ownership generation | No automatic toggle; explicit resolution → unowned |

**ACCEPT WITH CHANGES**
