# Feature Spec - R0-08 Minimal mouse-hook spike

Written: 2026-11-25, before Rust implementation. Owner: shell-engineer-windows.

Spec refs: [Windows integration, section 7](../../docs/PLATFORM/00-WINDOWS-INTEGRATION.md), [security](../../docs/SECURITY/00-SECURITY-AND-PRIVACY.md), [Rust migration](../../docs/ARCHITECTURE/03-RUST-MIGRATION.md), [testing](../../docs/TESTING/00-TESTING-STRATEGY.md), [task card](../../TASKS/RUST-MIGRATION.md).

## Problem and scope

Quick-hide needs reliable recognition of an empty-desktop double-click without delaying native input, suppressing the Windows context menu or retaining input history. WH_MOUSE_LL supplies button events, not a dedicated reliable double-click notification. The Rust spike must establish callback, queue, consumer and shutdown behavior separately from desktop-host and icon-recovery acceptance.

The first isolated implementation is pure Rust queue and click-recognizer logic in `crates/drape-shell-windows/src/hook_state.rs`. It installs no hook, spawns no thread, calls no native API and performs no desktop mutation. It does not enable a capability or wire quick-hide to icon hiding. Full native callback/message-loop/hit-test implementation remains a later subset after this spec and source review. No hook is installed on the owner's current desktop during this continuation; native evidence belongs to an interactive checkpointed VM/test account.

Legacy [P0-07](./P0-07-mouse-hook.md) and [its source](../../spikes/p0-07-mouse-hook/Program.cs) are historical reference only. Their in-callback hit test, interpolated/unbounded event queue, latency lock/list and inferred double-click messages are not adopted. A class-name match alone does not prove an empty desktop. No C# result counts as Rust acceptance.

## Architecture and proposed isolated interfaces

No Core interface changes. Shell-local types contain only fixed-size owned values. Core/UI never receive raw hook data. Do not derive an input-record Debug representation that prints coordinates/timestamps.

- `ButtonEvent` identifies left/right down/up. `ButtonSample` holds that event, physical screen x/y and the native wrapping u32 millisecond timestamp. No keyboard data, injected pointer, path, window handle or growing history is retained.
- `HookQueue::new(NonZeroUsize)` performs fallible preallocation of fixed-capacity ring storage. `try_push(ButtonSample)` uses `Mutex::try_lock`, never waits, allocates or invokes a callback; full, contended or poisoned state reports a discontinuity and drops the sample. This is non-blocking admission, not a lock-free algorithm or a real-time guarantee.
- `HookQueue::poll()` runs on the consumer and returns `Empty`, `Event(sample)` or `Reset`. Any loss latches an atomic reset flag; producer admission stays closed while reset is pending. The consumer discards all queued samples and emits Reset before any new sequence can be accepted. All queues have one intended producer (hook thread) and one consumer; synchronization prevents memory races but does not define multi-producer gesture ordering.
- `HookQueue::mark_discontinuity()` latches the same reset on disable, shutdown, host/session loss or explicit cancellation. Reset means logical deletion of transient records, not a forensic memory-erasure guarantee. Constructor allocations may fail; no queue growth follows successful creation.
- `DoubleClickSettings::new(time_ms, width_px, height_px)` validates positive supplied system settings; time is below half the u32 timestamp range so wraparound versus stale/backward input has a bounded interpretation. No environment or clock read occurs in pure logic.
- `DesktopHit` is `Empty { generation }`, `Occupied` or `Unknown`, supplied by a verified off-callback hit test. A generation changes after host/session replacement. Unknown never means empty.
- `DoubleClickRecognizer::observe(sample, hit)` processes complete left down/up pairs, retaining at most one pressed button and one completed candidate. It emits a boolean intent only after two complete valid clicks. Both clicks must be empty on the same validated generation. The interval between their downs is within the supplied time; press/release and click separation stay within the system rectangle. Right-button events, malformed ordering, unknown/occupied hits, expired/backward timestamps and generation changes discard the sequence. A third click starts a fresh sequence after emission.
- `DoubleClickRecognizer::reset()` clears all candidates. The consumer must call it on Queue Reset, disable, timeout, host/session loss and any separately detected drag/movement cancellation. This isolated subset does not implement movement tracking, right-drag or native hit testing and cannot claim to reject a drag that leaves and returns between button observations.

Rectangle coordinates use i64 arithmetic around the first physical screen point, including negative origins and i32 extremes. A system width/height describes a half-open rectangle: delta is at least `-(extent / 2)` and less than `extent - extent / 2`. Do not hide boundary behavior with floating-point rounding.

## Full native lifecycle contract (not implemented by the pure subset)

Consumer ordering: `poll()` has one serialized consumer. Its atomic loss check is the dequeue linearization point. A discontinuity racing after that check may follow one already-claimed sample. Handle that result synchronously, process Reset before later samples, and revalidate enabled state and host/session generation before dispatching any intent. Disable/host-loss commands and dispatch must be serialized by the consumer owner; discontinuity does not revoke an action already dispatched. This is an integration requirement, not an implemented native consumer.

The pure `HookConsumer` implements that serialized ordering without a native lifecycle. Initial polling establishes a context and resets the queue before consuming samples: queued records from before validation cannot be attributed to the current generation. A contended poll can yield Empty while the reset remains pending; no later sample bypasses that reset. Context is revalidated after hit testing and immediately before synchronous intent dispatch. `reset(queue)` clears recognizer candidates immediately, invalidates the consumer context and latches queue discontinuity for serialized idle-timeout, movement cancellation or shutdown commands. The future owner must deliver those commands even when there are no new button events and for disable/re-enable transitions between polls; the pure consumer starts no timer and cannot detect intervening movement. This 2026-11-26 clarification implements the existing cancellation and stale-input requirements without changing Core interfaces or native acceptance.

1. Initialize the dedicated hook/message-loop thread and bounded queue before installing WH_MOUSE_LL. Keep callback state alive until unhooking and all in-flight callback work finish. Installation failure reports disabled quick-hide/right-drag support; it never hides icons.
2. Callback forwards negative hook codes directly. For eligible button events it copies only validated fixed-size native fields, tries admission, then forwards through CallNextHookEx. No hit test, filesystem/registry/network/logging, shell extension, substantial allocation, blocking lock or user/UI callback is allowed.
3. Contain Rust panics inside the extern callback before they can unwind across FFI. Record only a bounded fault flag, invalidate the sequence and forward input. Do not run an allocating/logging panic hook in the callback path. Catch-unwind cannot make abort, access violation or corrupt native pointers recoverable; checked native ownership/API contracts and VM failure evidence remain required.
4. A bounded worker/consumer performs verified desktop hit tests and recognition. Never send an in-process LVM_HITTEST pointer into Explorer. A UIA or reviewed cross-process alternative must prove target/session/generation and bounded timeout/lifetime behavior. Unknown, inaccessible or stale targets produce no gesture.
5. Native double-click settings come from GetDoubleClickTime and the two system double-click rectangle dimensions. Physical coordinates are not mixed with Slint DIP. Refresh settings safely outside callbacks and reset candidates when settings/session/host change.
6. On overflow/consumer loss, reset queued events and all candidate state before accepting another sequence. Transient input is discarded after completion, timeout, cancellation, shutdown and host/session loss; never persisted or logged. Do not publish raw samples over Guard IPC.
7. Shutdown stops admission, requests hook-thread shutdown, unhooks on the owning thread, drains/clears state, terminates its message loop and joins before releasing callback storage. A timeout is not authorization to terminate a thread or free live native state. Plain right-click remains forwarded; no input suppression is introduced by this spike.

## Desktop safety, security and data

No icon visibility change, Guard interaction, recovery-state schema, user-file mutation, Explorer termination, registry write, network call or elevation. Quick-hide intent is not authority to hide native icons: later integration must satisfy the armed recovery transaction and capabilities. No persisted hook settings/schema changes in this task. Samples exist only in bounded transient memory for gesture decisions. Diagnostics expose aggregate counts/latency only, without coordinates, filenames, per-event timing records or click history.

## Verification and acceptance

Write pure behavioral tests before implementation; QA alone runs the sequential validation queue. Tests cover FIFO/capacity, loss discarding all queued history, contention returning promptly with reset, repeated reset, settings validation, valid complete click pairs, timing/rectangle boundaries, wrapping time, negative/extreme coordinates, malformed order, occupied/unknown targets, generation changes, right-button cancellation, reset/timeout and no reuse after emission. A mutation removing loss-to-reset behavior must fail a named assertion rather than a compile error. A second mutation permitting cross-generation click pairing must fail its named test. Constructor failure and poisoned synchronization fail closed; unit fakes do not prove native callback latency.

Native VM acceptance remains required: exact Windows 10 22H2 and Windows 11 builds, DPI 100/150/200/300 percent including mixed-scale negative-origin monitors, input/antivirus observations and workload. Record actual callback entry-to-return average, p99/max and sample count over at least 1,000 events; average must be below 1 ms and no callback may exceed the platform timeout. Measure the complete callback including forwarding, without taking a lock or growing a latency list there. Use preallocated aggregate instrumentation reviewed before the run. Validate left clicks on empty desktop versus icons/Drapes/other applications, plain right-click context menu, movement/drag cancellation, overflow, slow/failed hit tests, hook-install failure, repeated enable/disable, message-loop errors, session/host loss and clean shutdown. Explorer restart is manual in a checkpointed VM only; no automation terminates Explorer or changes registry/system state.

## Not determined

The pure subset does not establish real hook installation, callback panic-hook behavior, latency, AV acceptance, native empty-desktop hit tests, drag recognition, message-loop shutdown, Windows hook timeout handling, UI wiring, quick-hide safety or the Windows/DPI/monitor matrix. Production queue capacity is not selected; caller-supplied bounded capacity is a spike parameter. Native APIs/features and any interface extension receive review before implementation. No architecture deviation or scope removal is introduced.
